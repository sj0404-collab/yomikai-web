# models/ — обученная здесь модель распознавателя строк

`rec_synth.onnx` — то, что получается из `tools/train_curriculum.sh` за 7 минут на
двух ядрах CPU. Обучена на синтетических строках: слова взяты из вшитого словаря
(487 247 слов), нарисованы шрифтами DejaVu, испорчены наклоном, размытием, шумом,
инверсией, бликами и обрезкой.

| | |
|---|---|
| размер | 3,88 МБ, один файл (веса внутри) |
| параметров | 0,97 млн |
| вход | `float32 [1, 3, 48, W]`, W кратно 8, хвост дополнен нулями |
| выход | `float32 [1, W/8, 519]` — вероятности; 0 = blank, 1…517 = `tools/rec_charset.txt`, 518 = пробел |
| проверка контракта | `python3 tools/check_onnx_contract.py models/rec_synth.onnx` → ГОДИТСЯ |
| качество | CER 6,7 % на отложенных синтетических строках (путь ONNX) |

## Как попробовать в приложении

1. Открыть `koma-web.html` в Chrome.
2. ⚙ → Модели → выбрать два файла: `rec_synth.onnx` (как `cyrillic.onnx`) и
   `tools/rec_charset.txt` (как `cyrillic.txt`). Детектор `detection.onnx` — свой,
   от него зависит только поиск облачков, не чтение строк.
3. «Проверить движок».

## Чего эта модель НЕ делает

Она не заменяет `koma_rec` из АПК на настоящей манге: там свои шрифты,
текстуры и повреждения, а здесь обучение шло на синтетике. Это доказательство
работоспособного пути «данные → обучение → ONNX → приложение», а не новая
продакшн-модель. Для настоящего улучшения нужны кропы строк с транскриптами
(`tools/train_rec.py --crops`) и GPU: на двух ядрах CPU `koma_rec` не переобучить.
