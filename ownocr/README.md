# ownocr — свой OCR с нуля, без ONNX и TFLite

Маленький движок распознавания, целиком собранный здесь: свои признаки буквы, свой
классификатор на numpy, свой разрез строки на буквы, свой сборщик слов, свой
интерфейс обучения «учитель–ученик» на одном листе из 130 кириллических шрифтов.
Ни одной скачанной модели, ни ONNX, ни TFLite, ни torch. Только numpy, OpenCV (как
калькулятор для картинок) и PIL (чтобы нарисовать лист).

```
модель:  37 113 чисел, 136 КБ (npz)
признаки: 135 чисел на букву
скорость: 73 мс на строку 1703×34 px на одном ядре
обучение: 6 уроков, ~35 секунд на 2 ядрах
```

## Как это работает

### 1. Что видит ученик (features.py)

Буква приводится к квадрату 24×24, и с неё снимаются три вещи:

* **где краска** — плотность чернил по сетке 6×6 (36 чисел);
* **куда идут штрихи** — 8 направлений Собеля в каждой из 9 клеток (72 числа);
* **форма** — профили по горизонтали и вертикали (24 числа), пропорция,
  заполненность, число дырок внутри (3 числа).

Итого 135 чисел. Никаких «фич из коробки» — это арифметика над пикселями.

### 2. Как ученик думает (model.py)

Softmax-регрессия с одним скрытым слоем 192, ReLU, перекрёстная энтропия + L2,
Adam, градиенты выписаны руками (backprop). Обучение — это буквально
`−log p(верный класс)`, то есть логарифм правдоподобия: в журнале видно, как он
падает от урока к уроку.

### 3. Лист (data.py, scripts/01–02)

Один лист — 130 шрифтов, 90 знаков в каждом (заглавные, строчные, цифры, знаки),
11 698 глифов. Каждая пятая строка (26 шрифтов) **отложена**: ученик никогда её
не видит, на ней только проверка. Рамка каждого глифа записывается в манифест,
поэтому «нарезка листа на буквы» честная, без угадывания.

### 4. Уроки (teach.py)

| урок | что делает | % верных на отложенных шрифтах |
|---|---|---|
| 1. Азбука | 12 чистых шрифтов, только заглавные и цифры | 77,5 |
| 2. Полный алфавит | те же шрифты, все 90 знаков | 83,7 |
| 3. Сорок шрифтов | +28 начертаний | 89,8 |
| 4. Весь лист | все 104 учебных шрифта | 93,2 |
| 5. Разбор ошибок | учитель находит худшие пары букв и даёт прицельные примеры | 93,6 |
| 6. Кегль и курсив | мелкий кегль, наклон, шум сканера | **94,1** |

Урок 5 — самое «учительское»: после проверки смотрим, какие пары ученик путает
(`З↔3`, `О↔0`, `Ъ↔Ь`, `Е↔Ё`), и поднимаем вес этих классов в 2,5 раза, добавив
ещё и синтетические копии с наклоном.

### 5. Чтение (engine.py)

1. **Убрать освещённость**: вычитаем размытый фон, растягиваем контраст, Отсу.
   (Просто Отсу на скане манги давало 21–32 % «чернил» и склеивало все буквы.)
2. **Полоса строки**: в кропе от детектора лежат обрезки соседних строк — берём
   полосу с наибольшим количеством чернил.
3. **Пятна** → склейка диакритики (точки «Ё», дужка «Й») → разрезание склеенных
   букв по долинам вертикальной проекции.
4. **Чтение**: 135 признаков → вероятности. Храним топ-5, они нужны дальше.
5. **Сборка слова**: свой beam search по топ-5, где к сумме `log p` прибавляется
   бонус словарю за известное слово (частота слова). Это чинит ровно те пары,
   которые одинаковы по форме: `З↔3`, `О↔0`, `Ъ↔Ь`, `Е↔Ё`.

### 6. Урок 7 — настоящая страница (lesson_real.py)

Лист печатный, манга нарисована рукой. Второй урок учителя: 41 строка с известным
текстом, каждая третья — контрольная. На учебных строках ученик режет кроп на
пятна, а учитель **выравнивает пятна с эталоном** динамическим программированием
(какое пятно какой букве соответствует, с ценой за пропуск) и даёт ему пары
«картинка–буква» с сильными упражнениями (наклон, жирность, шум, мелкий кегль).
Выравнивание, которому нельзя верить (пятен и букв не сошлось), отбрасывается —
иначе учитель учит мусору.

## Что получилось (честные цифры)

| проверка | результат |
|---|---|
| глифы 26 шрифтов, которых не было в обучении (N=2338) | **94,1 %** |
| те же глифы с наклоном/курсивом | 84,7 % |
| те же глифы в мелком кегле (45–70 %) | 72,7 % |
| строки прозы в отложенных шрифтах (36 строк, 12 шрифтов) | CER **23,1 %** |
| страница манги: 41 настоящая строка (словарь) | CER 42,4 %, по буквам **70,9 %** |

**Честно о манге.** На настоящей странице движок читает 7 из 10 букв, но строку
целиком — 6 из 41. Ошибки не в модели, а в разрезе: рукописные буквы касаются друг
друга, и разрез либо склеивает их, либо рвёт. Урок 7 это подтвердил: он поднял
чтение отдельных букв, но CER страницы не улучшил (46,1 → 47,0 % на контрольных),
и я оставил его как есть, а не подогнал под ответ.

Для сравнения: в приложении стоит обученная на сервере CTC-модель (7,9 МБ), у неё
на той же странице CER 3,2 %. То есть свой движок на 136 КБ — это 94 % на печатных
шрифтах и «на троечку» на рукописи. Заменять встроенную модель ему пока нечем,
но как проверка-второй-голос и как учебный стенд он работает.

## Запуск

```bash
python3 scripts/01_fetch_fonts.py          # скачать 130 шрифтов (~246 МБ, в /var/tmp)
python3 scripts/02_make_sheet.py           # нарисовать лист + манифест (4 с)
python3 scripts/03_teach.py                # 6 уроков, ~35 с, журнал out/teacher-log.txt
python3 scripts/04_lesson_real.py           # урок 7 на настоящей странице
python3 scripts/05_metrics.py               # итоговые цифры в out/metrics.json
```

Своя «песочница» для проверки руками:

```python
from ownocr.engine import OwnOCR
ocr = OwnOCR('model')                       # 136 КБ, грузится мгновенно
print(ocr.read_line("моя_строка.png")['text'])
```

## Что можно улучшить дальше (по порядку пользы)

1. **Разрез строки** — самое узкое место. Нужен разрез по «скелету» буквы
   (тонкая линия внутри пятна), а не по проекции: тогда склеенные рукописные
   буквы делятся по-настоящему.
2. Больше настоящих строк для урока 7 (сейчас 27 учебных): по буквам уже 71 %,
   и с 300–500 строками это выйдет на 85 %+.
3. Скрытый слой 384 вместо 192 — модель останется в пределах 500 КБ.
4. Мелкий кегль: учить не на уменьшенных копиях, а на отдельном листе, набранном
   в 18–22 px (там сейчас 72,7 %).
