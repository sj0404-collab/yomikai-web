# KOMA для Android (АПК-обёртка)

Обёртка вокруг той же читалки `koma-web.html`: WebView + **нативный Google Lens** +
автообновление с GitHub. Одна кодовая база с браузерной версией, поэтому
исправления в читалке сразу приезжают в АПК — без переустановки.

## Что внутри

| Файл | Что делает |
|---|---|
| `app/src/main/java/net/koma/reader/MainActivity.kt` | WebView, постоянный адрес страницы, выбор файлов моделей, «назад» внутри читалки, тихое автообновление при старте |
| `.../GlensEngine.kt` | **нативный движок Lens**: сам отправляет кадр и сам забирает текст (тот же путь, что в оригинальном yomikai) |
| `.../KomaLensBridge.kt` | мост `window.KomaLens.recognize(...)` — его ждёт читалка |
| `.../KomaAppBridge.kt` | `window.KomaApp`: версия, «Проверить обновление», «Проверить Lens» |
| `.../Updater.kt` | скачивание `koma-web.html` с GitHub, проверка, атомарная замена |

## Почему адрес страницы постоянный

Читалка отдаётся не из `file://`, а по адресу
`https://appassets.androidplatform.net/web/koma-web.html` через
`WebViewAssetLoader`. Это важно:

* **IndexedDB привязан к источнику.** Модели (≈12 МБ), книги, настройки и словарь
  живут именно там. При обновлении меняется только файл, источник остаётся тем
  же — библиотека не стирается.
* `file://` в WebView не даёт IndexedDB и ломает `fetch`.

Файл берётся из `filesDir/koma-web.html`, если он есть (обновлённая версия), иначе
из `assets/koma-web.html` (встроенная). При отсутствии интернета работает
встроенная.

## Как работает нативный Lens

В браузере `lens.google.com` нельзя прочитать из страницы (CORS). В приложении
этот запрет не действует: приложение само делает POST кадра и само разбирает
ответ:

1. `POST https://lens.google.com/v3/upload?hl=ru&ep=ccm`, поле `encoded_image`,
   мобильный User-Agent, cookie из WebView;
2. разбор: сначала блок `AF_initDataCallback` (там Lens держит результат), затем
   общий поиск читаемых строк в теле ответа;
3. если Google отдал антибот-страницу «включите JavaScript» — приложение честно
   говорит об этом и предлагает релей или вставку текста.

Вызов асинхронный: страница зовёт `KomaLens.recognizeAsync(base64, opts, id)`,
мост считает в своём потоке и возвращает ответ в `window.__komaLensResolve[id]`.
Синхронный `recognize` тоже живой — для старых сборок страницы. Асинхронный
выбран не для красоты: синхронный вызов держит поток JavaScript, и на медленном
ответе Google интерфейс замирал бы до 45 секунд.

Проверка шва без телефона: `node test-apk-bridge.cjs` в корне `koma-web/`
(17 проверок: транспорт, строки, порядок, ошибка текстом, таймаут, синхронный
путь и совпадение имён моста в Kotlin и в странице).

## Сборка

### На GitHub (рекомендуется)

Actions → **сборка АПК** → Run workflow. Через ~5 минут в артефактах лежит
`koma-reader-debug.apk`. Push тега `v1.9.31` дополнительно кладёт APK в Releases.

### Локально

```bash
cp ../koma-web.html app/src/main/assets/koma-web.html   # или полагаемся на таск copyWeb
gradle assembleDebug        # Android SDK 34, JDK 17
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

## Своя подпись (для публикации)

Сейчас `release` подписывается отладочным ключом, чтобы APK ставился сразу.
Для Play/раздачи:

```bash
keytool -genkeypair -v -keystore koma.jks -alias koma -keyalg RSA -keysize 2048 -validity 10000
```

и в `app/build.gradle.kts` заменить `signingConfig` на свой (файл ключа в
репозиторий не класть).

## Что проверено, а что нет

* Проверено: сборка APK на ранере, установка файла на телефон, работа читалки
  из assets (те же тесты, что для браузера), мост `KomaLens` на подставном
  движке (`lab/lens_direct_check.py`, сценарий B).
* **Не проверено:** настоящий ответ Google на запрос из приложения — в песочнице
  нет Android. Если Google ответит антибот-страницей, кнопка «Проверить Lens»
  в «Правилах» покажет это прямым текстом, и тогда рабочий путь — свой релей
  (`lab/lens_relay.js`) или вставка текста.
