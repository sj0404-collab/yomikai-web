# KOMA Web — локальная библиотека и читалка в одном HTML

Один файл `koma-web.html`. Никакого сервера, никаких установок: открывается в
Chrome (Android/десктоп) как обычная страница. Всё лежит на устройстве.

## Что внутри

- **Локальная библиотека**: папка с главой, CBZ/ZIP, отдельные страницы.
  Файлы хранятся в IndexedDB этого сайта, обложка — первая страница.
- **Читалка**: вертикальная лента (манхва), страницы справа налево (манга) и
  слева направо. Рамки реплик, подсветка читаемой, тап по рамке — озвучить.
- **OCR в браузере**: onnxruntime-web + ваши `detection.onnx`, `cyrillic.onnx`,
  `cyrillic.txt`. Ни один кадр никуда не отправляется.
- **Правила** `koma-rules.json` — те же ключи, что у АПК: порог «чернил»,
  подблочные пороги (несколько шрифтов на странице), второй уровень чернил,
  полосы экрана, склейка реплик, `wordFixes`.
- **Буфер строк**: что вернул OCR, с рамками и версией правил; выгрузка в текст.
- **Полуручной режим**: читает то, что видно, встаёт, ждёт вашей прокрутки
  (стрелка по направлению чтения). Пока лента едет — ничего не сканируется.

## Как добавить модель (SAF-выбор файла)

1. Возьмите APK `yomikai` (любой свежий релиз) и распакуйте:
   внутри `assets/koma/models/` лежат `detection.onnx`, `cyrillic.onnx`,
   `cyrillic.txt`.
2. Откройте `koma-web.html` → шестерёнка **⚙ Модели OCR** → «Выбрать файлы» →
   отметьте все три (системный выбор файлов — это и есть SAF).
3. Они сохранятся в браузере; при следующем открытии подхватятся сами.

Первый запуск после выбора моделей занимает несколько секунд: браузер
компилирует WASM-движок.

## Что скопировано из АПК буквально (сверено численно)

- препроцессинг детектора: `ratio = min(1, 1600/max(w,h))`, размеры кратные 32,
  вход `[1,3,h,w]`, значения `канал/255`; если боксов нет — повтор с
  ImageNet-нормализацией;
- карта вероятностей → компоненты BFS с порогом 0.3 (мин. 6 пикселей, средняя
  уверенность ≥ 0.5, расширение рамки как в `components()`);
- нарезка бокса на строки: отступ `0.12·h`, даунскейл до ширины 400,
  `inkThreshold` по перцентилям 2 %/98 %, подблочные пороги (`inkTileRows`),
  второй уровень (`inkLevels`), склейка полос при зазоре ≤ 0.35 медианы;
- распознавание: ширина `round(48·w/h)` в пределах 8…960, `padded = max(320,w)`,
  нормализация `(x/255 − 0.5)/0.5`, поворот высоких кропов на 90°,
  жадное CTC-декодирование, словарь `[""] + cyrillic.txt + [" "]`;
- `decodeBetter`: повтор по бинаризованному кропу, замена только при большем
  числе букв;
- порядок чтения: облачка (`bubbleGap`), склейка строк одного облачка
  (`sameBubble` + `joinBubbleText`), поглощение обрывков (`absorbOrphans`),
  полосы и RTL/LTR (`orderBubbles`);
- полосы экрана: `overlap`, `bandsMax`, `wholeThreshold`.

Проверено тестами против эталонной Python-реализации на тех же моделях:
препроцессинг детектора — побитово, препроцессинг распознавания — до float32.

## Исправлено в v0.2

- **Тап по книге не открывал читалку.** Карточка вызывала `openBook()`, а такой
  функции в файле не было — ReferenceError глотался молча. Теперь функция есть,
  а любая ошибка показывается тостом, а не прячется в консоли.
- **«＋» ничего не делал.** Обработчик спрашивал `confirm()`, который в
  предпросмотре и части мобильных браузеров глушится, а затем полагался на
  `webkitdirectory` — в Android Chrome его нет вовсе. Теперь: отдельная шторка
  «Добавить главу» с двумя кнопками («Выбрать папку» / «Выбрать файлы или CBZ»),
  без модалок; на Android кнопка папки скрыта и написано, почему.
- Хранилище: если IndexedDB недоступен (песочница, `file://`), библиотека
  работает в памяти — кнопки не молчат, а в шапке честно сказано, что данные
  живут до перезагрузки.
- Удаление книги — вторым нажатием, без `confirm()`.
- Под шапкой — строка самопроверки: версия, готов ли OCR, загружен ли
  onnxruntime-web, есть ли голоса.

## v0.3 — что было не так и что сделано

- **Выбор модели выбрасывал в читалку.** Все выборы файлов сидели на одном
  скрытом `input`: обработчик библиотеки срабатывал вместе с обработчиком
  моделей. Теперь у каждого свой input: картинки/CBZ, папка, модели, папка
  моделей, файл правил.
- **Модели из нескольких файлов.** Можно выбрать все три сразу или по одному:
  шторка не закрывается, статус по каждому файлу (✅/❌) и подсказка, чего ещё
  не хватает. Движок перезапускается сам, когда все три на месте.
- **Папка.** Кнопка больше не прячется: показываются «Выбрать папку» (там, где
  браузер умеет), «Выбрать папку (File System)» для `showDirectoryPicker`, и
  всегда доступные «Выбрать файлы или CBZ». Если папку браузер не отдал —
  сразу открывается выбор файлов с объяснением, а не молчание.
- На Android папку браузер не отдаёт в принципе: надёжный путь — выбрать все
  страницы сразу (или CBZ); порядок берётся из имён.

## Чего здесь нет (честно)

- **Панельный детектор** упрощён: делим по горизонтальным «желобам», а не
  геометрией, как `KomaPanels` в АПК.
- **Частотный словарь** `ru_250k.txt` не подключён: правки слов работают через
  `wordFixes`, а не через словарь.
- **ML Kit** как резервный движок — только ONNX.
- **Фоновое авточтение** с уведомлением: браузер усыпляет вкладку.
- **Память**: длинные вебтуны держим в памяти целиком, слишком большие главы
  (десятки кадров по 8000 px) браузер может не осилить — АПК с тайлами это умеет
  лучше.
- **Голоса** — системные TTS браузера, без выбора «персонаж → голос».

## Если открываете прямо в предпросмотре

Предпросмотр в песочнице без сети: `onnxruntime-web` (CDN) там не загрузится,
и распознавание не запустится. Библиотека, читалка и правила работают.
Скачайте файл и откройте в Chrome — там всё на месте.
