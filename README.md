# KOMA Web — локальная библиотека и читалка в одном HTML

Один файл `koma-web.html`. Никакого сервера, никаких установок: открывается в
Chrome (Android/десктоп) как обычная страница. Всё лежит на устройстве.

## Что внутри

- **Локальная библиотека**: папка с главой, CBZ/ZIP, отдельные страницы.
  Файлы хранятся в IndexedDB этого сайта, обложка — первая страница.
- **Читалка**: вертикальная лента (манхва), страницы справа налево (манга) и
  слева направо. Рамки реплик, подсветка читаемой, тап по рамке — озвучить.
- **OCR в браузере**: onnxruntime-web + ваши `detection.onnx`, `cyrillic.onnx`,
  `cyrillic.txt`. Ни один кадр никуда не отправляется.
- **Правила** `koma-rules.json` — те же ключи, что у АПК: порог «чернил»,
  подблочные пороги (несколько шрифтов на странице), второй уровень чернил,
  полосы экрана, склейка реплик, `wordFixes`.
- **Буфер строк**: что вернул OCR, с рамками и версией правил; выгрузка в текст.
- **Полуручной режим**: читает то, что видно, встаёт, ждёт вашей прокрутки
  (стрелка по направлению чтения). Пока лента едет — ничего не сканируется.

## Как добавить модель (SAF-выбор файла)

1. Возьмите APK `yomikai` (любой свежий релиз) и распакуйте:
   внутри `assets/koma/models/` лежат `detection.onnx`, `cyrillic.onnx`,
   `cyrillic.txt`.
2. Откройте `koma-web.html` → шестерёнка **⚙ Модели OCR** → «Выбрать файлы» →
   отметьте все три (системный выбор файлов — это и есть SAF).
3. Они сохранятся в браузере; при следующем открытии подхватятся сами.

Первый запуск после выбора моделей занимает несколько секунд: браузер
компилирует WASM-движок.

## Что скопировано из АПК буквально (сверено численно)

- препроцессинг детектора: `ratio = min(1, 1600/max(w,h))`, размеры кратные 32,
  вход `[1,3,h,w]`, значения `канал/255`; если боксов нет — повтор с
  ImageNet-нормализацией;
- карта вероятностей → компоненты BFS с порогом 0.3 (мин. 6 пикселей, средняя
  уверенность ≥ 0.5, расширение рамки как в `components()`);
- нарезка бокса на строки: отступ `0.12·h`, даунскейл до ширины 400,
  `inkThreshold` по перцентилям 2 %/98 %, подблочные пороги (`inkTileRows`),
  второй уровень (`inkLevels`), склейка полос при зазоре ≤ 0.35 медианы;
- распознавание: ширина `round(48·w/h)` в пределах 8…960, `padded = max(320,w)`,
  нормализация `(x/255 − 0.5)/0.5`, поворот высоких кропов на 90°,
  жадное CTC-декодирование, словарь `[""] + cyrillic.txt + [" "]`;
- `decodeBetter`: повтор по бинаризованному кропу, замена только при большем
  числе букв;
- порядок чтения: облачка (`bubbleGap`), склейка строк одного облачка
  (`sameBubble` + `joinBubbleText`), поглощение обрывков (`absorbOrphans`),
  полосы и RTL/LTR (`orderBubbles`);
- полосы экрана: `overlap`, `bandsMax`, `wholeThreshold`.

Проверено тестами против эталонной Python-реализации на тех же моделях:
препроцессинг детектора — побитово, препроцессинг распознавания — до float32.

## v1.7 — рваные реплики и мусорные строки

Две вещи со страницы 1:

1. **Облачко рвалось на три реплики** («УЖЕ ПОРА НАЧИНАТЬ ВСТРЕЧУ,» / «ТАК ЧТО ЕЁ
   ВЫСОЧЕСТВО, ДОЛЖНО» / «БЫТЬ, ПРИБЫЛА.»). Причин было две:
   - `splitPanels` был упрощённой версией (резал по зазору 1.2 высоты строки).
     Теперь перенесён настоящий **XY-cut** из `KomaAutoRead.splitPanels`:
     `mergeByAxis`, пороги `Y_CUT=0.022` / `X_CUT=0.035` от медианной высоты
     строки, рекурсивно, с RTL-порядком колонок;
   - мой фильтр `mergeHeightRatio` сравнивал **габариты облачка**, а не высоту
     строки. После склейки двух строк высота облачка выросла втрое, и третья
     строка не приклеивалась. Теперь у облачка хранится `lh` — типичная высота
     строки, и сравниваются именно они.
2. **Мусор в озвучке** («ол кослл алмчлс», «сттангасоат», «Тг. чв»). Добавлен
   **словарь и языковая починка** (идея `KomaWords.kt`):
   - `ru_250k.txt` берётся из того же APK (`assets/koma/dict/`) — кнопка
     **«Словарь ru_250k»** в ⚙ Модели, хранится в браузере, в файл не вшит;
   - слова не из словаря правятся одним редактированием
     («ПОШЕВЕАИТЬСЯ» → «ПОШЕВЕЛИТЬСЯ», «СЮОДА» → «СЮДА»), регистр сохраняется;
   - строка, где больше `junkRatio` (0.6) слов нет в словаре, — не реплика и в
     озвучку не попадает.

Тесты: `test-words.cjs` (правка слов, отбрасывание мусора, «верная реплика не
тронута») и проверка XY-cut на облачке из трёх строк.

## v1.6 — «стою на первой странице, а распознаёт не то»

Причина: `Reader.page` менялся **только** внутри обработчика `scroll` на
`#strip` и только когда у страницы уже был загружен образ. При ленивой загрузке
незагруженные страницы имели высоту 0, лента прыгала, а индекс «застревал» на
той странице, куда его увели авточтением. Отсюда шапка «4 из 20» и шторка
«Текст страницы 4», когда на экране была первая.

Исправлено:

- **`pageAtViewport()`** — страница определяется по геометрии: та, что занимает
  большую часть экрана (плюс ориентир по центру). Вызывается на каждом кадре
  прокрутки (rAF), на `scrollend`, `resize`, `orientationchange`,
  `visualViewport.resize` и после загрузки каждого образа;
- **`syncPage()`** — сверяет сохранённый индекс с экраном, обновляет шапку и
  подгрузку соседей; шторка «Текст страницы» вызывает её при открытии;
- **место под страницу резервируется заранее** (`aspect-ratio`): пропорция
  берётся из уже открытых страниц книги или средняя по книге, поэтому лента
  больше не прыгает при подгрузке;
- **в шторке появилась навигация по страницам**: «◀ стр. 3 · из 20 · стр. 5 ▶» —
  можно распознать и прочитать любую страницу, не двигая ленту; если выбранная
  страница не та, что на экране, это написано прямо в заголовке;
- **порядок починки как в АПК**: нормализация → `fixLookalikes` → фильтр языка
  (раньше фильтр мог выбросить слово, записанное латиницей).

Тест: `test-page.cjs` (на верху ленты определяется стр. 1, застрявший индекс 4
исправляется, стык страниц решается по площади на экране).

## v1.5 — про SAF и выбор папки (честно)

**Android SAF из веб-страницы вызвать нельзя.** SAF — это API Android для
нативных приложений; браузер его не отдаёт. Ближайшие замены:

| Что | Где работает | Ограничение |
|---|---|---|
| `showDirectoryPicker()` (File System Access) | Chrome/Edge на десктопе; **Chrome для Android с версии 132** (январь 2025), WebView 132+ | только HTTPS или `file://`, не работает в Firefox/Safari |
| `<input webkitdirectory>` | десктопные Chrome/Firefox/Safari | на Android не поддерживается вообще |
| выбор нескольких файлов / CBZ | везде | папку не отдаёт |

Поэтому в шторке «Добавить главу»:

- кнопки **не прячутся**: видно, что они есть и почему недоступны;
- под ними строка «Ваш браузер: …» — с версией Chrome, если папка появится
  после обновления;
- **новое: «Куда добавить»** — можно доливать страницы в уже существующую главу
  (`Library.appendTo`), нумерация продолжается без дыр. Это и есть рабочий путь
  на Android: файловый выбор редко отдаёт все 20 страниц за один раз;
- если браузер не умеет папку, нажатие объясняет причину тостом, а не молчит.

Тест: `test-files.cjs` (Android Chrome 130 → папка недоступна, кнопки
заблокированы с объяснением; `appendTo` даёт 4 страницы с индексами 0..3).

## v1.4 — «Распознать заново» не работало

На скриншотах было видно: шапка читалки показывает «3 из 20», а шторка —
«Текст страницы 2». Три отдельные ошибки:

1. **Сканировалась не та страница.** Кнопка звала `scanCurrent(true)`, а тот
   берёт «текущую» страницу в момент вызова. К этому моменту лента уже уехала
   на страницу 3 — поэтому страница 2 не пересканировалась ни разу.
   Теперь есть `scanPage(i)`: страница задаётся явно, кнопка берёт её из шторки
   (`Reader.textPage`).
2. **Шторка закрывалась перед сканированием**, а результат рисовался только
   «если шторка открыта» — значит не рисовался никогда. Теперь шторка остаётся
   открытой, в ней идёт прогресс (`Распознаю страницу 2 заново… 3/9`), кнопка
   блокируется, по окончании текст перерисовывается, в статистике появляется
   «обновлено 22:04:35».
3. **Молчаливый выход при занятом движке.** `if (State.scanning) return` — если
   в этот момент распознавалась другая страница, нажатие не делало ничего и
   ничего не сообщало. Теперь запрос встаёт в очередь и об этом говорится.

Плюс:

- **таймаут IndexedDB (3 с)**: если браузер не ответил, хранилище уходит в
  память. Раньше запись могла не завершиться никогда, и всё «висело» молча;
- открытие «Текст страницы» **останавливает авточтение** — иначе лента уезжает,
  пока читаешь текст, и кажется, что текст не тот;
- в шапке шторки пишется, где сейчас лента: «Текст страницы 2 · лента на стр. 3».

Тест: `test-rescan.cjs` (сканируется страница из шторки, буфер перезаписывается,
соседняя страница не тронута, второе нажатие встаёт в очередь и досканируется).

## v1.3 — порядок чтения

Замер: 4,4 с на страницу (детектор 1,9 + распознавание 2,5, 9 строк) — приемлемо.
А вот порядок реплик был неверный: «Я ТОЖЕ ТАК СЧИТАЮ» уезжало после «БОЛЬШЕ
ПРИВЛЕКАЮТ».

Причина: `rtl` брался из **режима прокрутки** (`mode === 'rtl'`). Для
вертикальной ленты это всегда `false`, поэтому и строки внутри реплики, и
облачка сортировались слева направо.

Исправлено:

- **направление чтения — отдельная настройка** `dir` (`rtl` по умолчанию),
  чипы «Справа налево / Слева направо» в настройках читалки, выбор помнится для
  книги; смена направления пересортировывает уже распознанное без повторного OCR;
- **склейка строк внутри реплики** как в `KomaAutoRead`: «ВЫСО-» + «ЧЕСТВО» →
  «ВЫСОЧЕСТВО», обрывок в 1–2 буквы приклеивается без пробела;
- **`KomaText.cleanSpeech`**: двойники латиницы/греческого/цифр
  («HETΛOXO» → «НЕТЛОХО», «MHE TAK» → «МНЕ ТАК», «3ВУ4ИТ» → «ЗВУЧИТ»),
  склейка цепочек одиночных букв («в д а ль» → «вда ль», как в АПК).

Тест: `test-text.cjs`.

## v1.2 — скорость и кэш

Замер на телефоне: **10,2 с на страницу**. Что сделано:

- **Кэш страниц.** Распознанная страница сохраняется в буфер и при повторном
  открытии книги/включении чтения больше не гоняется через модели. При старте
  книги выводится «Из буфера: N стр. уже распознаны». Повтор — только кнопкой
  «Распознать заново».
- **Замер по этапам.** Тост и шторка «Текст страницы» теперь показывают разбивку:
  `детектор X с + распознавание Y с, N кропов`. Видно, что именно медленно.
- **Меньше прогонов распознавания.** Правило `decodeRetryBelow` (по умолчанию 1):
  бинаризации запускаются только если из кропа не вышло ни одной буквы. Было «<3
  букв → ещё два прогона модели», то есть до трёх проходов на строку.
- **Повтор детектора** (`detRetry`, по умолчанию true) — только когда боксов 0.
- **Чтение не начинается во время сканирования.** Раньше в этот момент
  показывалось «На этой полосе нет распознанного текста» — теперь «Распознаю
  страницу, начну читать сразу после» и чтение стартует само.

Тест: `test-cache.cjs` (кэш не запускает модель, правило `decodeRetryBelow`
управляет числом прогонов).

## v1.1 — «Cannot read properties of undefined (reading 'data')»

`session.run()` в onnxruntime-web возвращает **Promise**, а код читал результат
сразу: `out[OCR.det.outputNames[0]].data`. В браузере это давало ровно эту
ошибку. Node-заглушки в моих тестах возвращали объект синхронно — поэтому тесты
были зелёные, а на телефоне падало.

Что сделано:

- `detectBoxes`, `decodeCrop`, `decodeBetter` — асинхронные, результат
  дожидается;
- `runModel()` разбирает ответ в трёх формах: простой объект, `Map`, и случай,
  когда имя выхода не совпало (берётся первый по порядку);
- если выходов нет вовсе — понятная ошибка «детектор не вернула выходов»,
  а не «reading 'data'»;
- сообщение об ошибке в читалке теперь содержит место в коде;
- регресс-тест `test-async-run.cjs`: движок отвечает промисом, ответ в виде
  `Map`, несовпавшее имя выхода, пустой ответ.

## v1.0 — файл полностью автономен (7,6 МБ)

`onnxruntime-web 1.18.0` и оба WASM-бинаря (`ort-wasm-simd.wasm`,
`ort-wasm.wasm`) вшиты внутрь HTML: движок сжат gzip и лежит в base64, при
старте разжимается в памяти через `DecompressionStream` и отдаётся движку
blob-URL'ом через `ort.env.wasm.wasmPaths`. **Ни одного запроса в сеть.**

Заодно это объясняет «на телефоне через http ничего не нажимается»: внешний
`<script src="cdn.jsdelivr.net">` блокирует разбор страницы, пока не загрузится
или не отвалится по таймауту — а обработчики к этому моменту ещё не навешаны.
Теперь внешних скриптов нет вообще.

Проверено: разжатые бинари совпадают с CDN-файлами по md5
(`49460a4b…` и `d51675fd…`), сигнатура `\0asm` на месте, повторный вызов не
плодит Blob. Тест — `test-ort-wasm.cjs`.

Если под шапкой вместо `KOMA Web v1.0` видно «Скрипты страницы не выполнились» —
значит inline-JS на этой странице запрещён (CSP сервера), а не сломан файл.

## Исправлено в v0.2

- **Тап по книге не открывал читалку.** Карточка вызывала `openBook()`, а такой
  функции в файле не было — ReferenceError глотался молча. Теперь функция есть,
  а любая ошибка показывается тостом, а не прячется в консоли.
- **«＋» ничего не делал.** Обработчик спрашивал `confirm()`, который в
  предпросмотре и части мобильных браузеров глушится, а затем полагался на
  `webkitdirectory` — в Android Chrome его нет вовсе. Теперь: отдельная шторка
  «Добавить главу» с двумя кнопками («Выбрать папку» / «Выбрать файлы или CBZ»),
  без модалок; на Android кнопка папки скрыта и написано, почему.
- Хранилище: если IndexedDB недоступен (песочница, `file://`), библиотека
  работает в памяти — кнопки не молчат, а в шапке честно сказано, что данные
  живут до перезагрузки.
- Удаление книги — вторым нажатием, без `confirm()`.
- Под шапкой — строка самопроверки: версия, готов ли OCR, загружен ли
  onnxruntime-web, есть ли голоса.

## v1.9.3 — почему молчал голос

Сказано «голос не работает, а раньше работал». Причина не в моделях и не в TTS-движке — в двух местах, которые я сам тронул:

1. **Прокрутка к реплике съедала звук.** В v1.9.2 в `speakLine` перед `speechSynthesis.speak()` появился вызов `followLine` (подкрутить ленту, чтобы панель не закрывала текст). Любая ошибка геометрии (`querySelector` вернул null в момент перестройки ленты, нулевая высота страницы) вылетала наружу — и `speak()` просто не вызывался. Панель при этом показывалась, поэтому выглядело как «голос сломался». Теперь прокрутка идёт ПОСЛЕ `speak()` и в `try/catch`.

2. **Браузер молча отбивал озвучку.** Chrome/WebView разрешает `speechSynthesis.speak()` только «из жеста». Между нажатием ▶ и `speak()` у нас есть `await` (ожидание распознавания, чтение буфера) — жест теряется, `speak()` отбивается с `not-allowed`, и раньше об этом никто не сообщал. Теперь:
   - `TTS.prime()` вызывается прямо в обработчике нажатия (▶, «Прочитать» в шторке, стрелка полуручного режима) и разблокирует синтезатор пустой фразой нулевой громкости;
   - `u.onerror` показывает причину: «Браузер не разрешил озвучку — нажмите ▶ ещё раз», «Голос не сказал: <код>», «Система не дала ни одного голоса: Настройки Android → Синтез речи».

3. **Пропавший голос.** `TTS.pickVoice()` сверяет сохранённый голос с теми, что реально есть сейчас. Если сохранённый исчез (перезапуск WebView, смена TTS-движка), берётся русский по умолчанию — и об этом говорится тостом, а не молча.

**Проверки:** `check.py` — 446 определений, 93 id; 16 тестовых файлов + `/tmp/test_logic.js` — ALL PASSED. Новый `test-voice.cjs`: голос уходит в синтезатор; падение прокрутки не отменяет звук; `not-allowed` объясняется; исчезнувший голос заменяется русским с предупреждением; пустой список голосов объясняется; `prime()` разблокирует синтез.

- `contrast` — растяжение диапазона яркости (бледная каллиграфия на белом);
- `binary` / `binary-inv` — две полярности бинаризации.
В отчёте шторки видно, какая подготовка сработала («детектор нашёл со 2-й попытки: контраст / бинаризация / инверсия / нормализация кадра») — а не молчаливый успех.

**2. Проход по крупному тексту (`recognizeLargeBox`).** Для блока, чьи строки выше типичной для страницы в 1,8 раза:
- кроп берётся с отступом 10 % и увеличивается так, чтобы большая сторона была ≈1200 px (коэффициент 2–4);
- детектор прогоняется по увеличенному кропу — блок делится на строки;
- если детектор всё равно вернул один бокс, строки режутся напрямую по увеличенному кропу;
- каждая строка распознаётся отдельно, координаты пересчитываются обратно на страницу, рамки стоят на месте.

**3. Выбор варианта по качеству (`qualityOf`).** Сравниваются тексты первого и второго прохода: побеждает тот, где больше слов, известных словарю (с учётом словоформ), при равенстве — больше букв. «будучи» (из словаря) вытесняет «будучиг».

**Проверки:** `check.py` — 493 определения, 94 id; 19 тестовых файлов — ALL PASSED. Новый `test-secondpass.cjs`: детектор повторяется на другой подготовке кадра; повтор виден в отчёте; при найденных боксах лишних прогонов нет; вариант с настоящими словами оценивается выше.

## v1.9.10 — дочинка отдельных слов, минуя уже верные

По просьбе: перебор — только по битым словам, верные не трогать.

**Как работает `refineBrokenWords`:**
1. Строка режется на слова по словарю (`[\p{L}]{2,}`), каждое проверяется: известно оно или это словоформа.
2. Если все слова верны — выходим сразу, ни одной попытки перебора (тест это фиксирует).
3. Если есть битые — строка режется по столбцовой проекции «чернил» на кропы слов. Замена возможна, только если число кропов совпало с числом слов (иначе не рискуем).
4. По кропу битого слова гоняются варианты: как есть → с полями → увеличение ×2 → поля+×2 → контраст. Берётся первый кандидат, который (а) состоит только из букв, (б) отличается по длине от оригинала не больше чем на одну букву, (в) есть в словаре или выглядит словоформой.
5. Слово подменяется в тексте по своим индексам; верные слова и верные строки остаются байт в байт.

**Защита проверена на каллиграфии.** Кроп рукописного слова даёт «p», «тр», «wэ» — такие кандидаты отбрасываются, в тесте это отдельный кейс. Поэтому на титуле этой страницы дочинено 0 слов: честно, а не «подправили и стало хуже».

**Заодно вычищены мусорные строки,** которые всплыли при полностраничном прогоне: «АААААА» (капс с тройным повтором буквы) и «то н оо о оно» (длинная строка, где настоящих слов меньше половины).

**Проверки:** `check.py` — 542 определения, 94 id; 21 тест + `run_all.sh` — ВСЁ ПРОШЛО; новый `test-wordfix.cjs` (4 кейса: дочинка, сохранение верных слов, отсутствие перебора на верной строке, отказ от мусорного кандидата); `e2e.py` на реальной странице — 6 из 6.
